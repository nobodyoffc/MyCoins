     MyCoins - Multi-Coin Mobile Wallet

     Context

     Build a React Native (TypeScript) mobile wallet supporting BTC, ETH, BCH,
     FCH (Freecash), DOGE, USDT (ERC-20), USDC (ERC-20). One secp256k1 private
     key derives addresses for all coins. Users create password-based accounts
     where sha256(password) is the AES-GCM-256 encryption key and the first 6
     bytes of sha256(sha256(password)) (12-char hex) is the account ID. Keys are
      stored as encrypted JSON files on device.

     Architecture

     Project Structure

     mycoins/
     ├── src/
     │   ├── crypto/          # Pure crypto primitives
     │   │   ├── keys.ts      # secp256k1 key gen, import
     (random/hex/WIF/secret/pubkey)
     │   │   ├── hash.ts      # sha256, ripemd160, keccak256, hash160,
     doubleSha256
     │   │   ├── aes.ts       # AES-GCM-256 encrypt/decrypt
     │   │   ├── address.ts   # Pubkey → address for all coin types
     │   │   └── encoding.ts  # Base58Check, WIF, CashAddr, hex utils
     │   ├── coins/           # Coin-specific TX builders + config
     │   │   ├── types.ts     # CoinType enum, CoinConfig interface
     │   │   ├── registry.ts  # Coin params (version bytes, decimals, etc.)
     │   │   ├── btc/         # BTC tx-builder (bitcoinjs-lib Psbt)
     │   │   ├── bch/         # BCH tx-builder (SIGHASH_FORKID) + cashaddr
     │   │   ├── fch/         # FCH tx-builder (reuses BCH, prefix 0x23)
     │   │   ├── doge/        # DOGE tx-builder (BTC-style, prefix 0x1e)
     │   │   ├── eth/         # ETH tx-builder (ethers.js)
     │   │   └── erc20/       # ERC-20 transfer builder (USDT/USDC)
     │   ├── account/         # Account & key management
     │   │   ├── account.ts   # Account creation, ID derivation, password verify
     │   │   ├── keystore.ts  # Encrypted JSON file read/write
     │   │   └── key-manager.ts # Key CRUD (generate, import, list, select)
     │   ├── api/             # Configurable API layer
     │   │   ├── types.ts     # CoinAPI interface (getBalance, getUTXOs,
     broadcast, etc.)
     │   │   ├── api-registry.ts # Maps CoinType → provider
     │   │   └── providers/   # blockchair, etherscan, freecash, custom
     │   ├── store/           # Zustand state (account, wallet, settings)
     │   ├── screens/         # Login, KeyList, Dashboard, CoinDetail, Send,
     Receive, Settings
     │   ├── components/      # CoinBalanceCard, QRCode, AmountInput, etc.
     │   └── navigation/      # React Navigation (auth stack + main tabs)
     └── __tests__/           # Mirrors src/ structure

     Key Dependencies

     - Crypto: @noble/secp256k1, @noble/hashes (pure JS, no native build issues)
     - AES: @noble/ciphers (pure JS AES-GCM, no native dependency)
     - UTXO TX: bitcoinjs-lib v7, ecpair, tiny-secp256k1, bs58check
     - BCH addr: cashaddr
     - ETH/ERC-20: ethers v6
     - Storage: react-native-mmkv (settings), react-native-fs (keystore files)
     - Navigation: @react-navigation/native v7
     - State: zustand
     - QR: react-native-qrcode-svg, react-native-vision-camera

     Account & Key Model

     Password → sha256(password) = AES-GCM-256 key
              → sha256(sha256(password))[0:6].hex() = 12-char account ID

     Keystore file: {documentsDir}/keystores/{accountId}.json
     {
       accountId: "a1b2c3d4e5f6",
       version: 1,
       keys: [{
         id: "FxxxxFCHaddress",       // FCH address = key identifier
         iv: "hex...",                // random 12-byte nonce
         ciphertext: "hex...",        // AES-GCM encrypted privkey
         isWatchOnly: false,
         addresses: { BTC: "1...", BCH: "bitcoincash:...", FCH: "F...", DOGE:
     "D...", ETH: "0x..." }
       }]
     }

     Address Derivation (from one pubkey)

     ┌──────┬─────────────────────────────────────────┬──────────────────┐
     │ Coin │                 Method                  │      Result      │
     ├──────┼─────────────────────────────────────────┼──────────────────┤
     │ BTC  │ Base58Check(0x00 + hash160(pubkey))     │ 1xxx             │
     ├──────┼─────────────────────────────────────────┼──────────────────┤
     │ BCH  │ CashAddr(hash160(pubkey))               │ bitcoincash:qxxx │
     ├──────┼─────────────────────────────────────────┼──────────────────┤
     │ FCH  │ Base58Check(0x23 + hash160(pubkey))     │ Fxxx             │
     ├──────┼─────────────────────────────────────────┼──────────────────┤
     │ DOGE │ Base58Check(0x1e + hash160(pubkey))     │ Dxxx             │
     ├──────┼─────────────────────────────────────────┼──────────────────┤
     │ ETH  │ keccak256(uncompressed_pubkey[1:])[12:] │ 0xxx             │
     ├──────┼─────────────────────────────────────────┼──────────────────┤
     │ USDT │ Same as ETH                             │ 0xxx             │
     ├──────┼─────────────────────────────────────────┼──────────────────┤
     │ USDC │ Same as ETH                             │ 0xxx             │
     └──────┴─────────────────────────────────────────┴──────────────────┘

     TX Building

     - BTC/DOGE: Standard P2PKH via bitcoinjs-lib Psbt (DOGE uses custom network
      params)
     - BCH/FCH: Custom sighash with SIGHASH_FORKID (bit 6 set, BIP143-like
     preimage includes input value). ~100 lines on top of bitcoinjs-lib
     serialization. FCH reuses BCH builder with different address prefix only.
     - ETH: ethers.Transaction for EIP-1559 TX construction + signing
     - ERC-20: ETH TX where data = ABI-encoded transfer(address,uint256), to =
     contract address

     Navigation Flow

     Auth Stack: LoginScreen → CreateAccountScreen
     Main Tabs:
       Wallet: KeyList → Dashboard → CoinDetail → Send/Receive/TxDetail
       Keys:   KeyList → GenerateKey / ImportKey
       Settings: API config, account management

     Implementation Phases

     Phase 1: Crypto Core

     1. Init React Native project with TypeScript
     2. src/crypto/hash.ts — all hash functions
     3. src/crypto/keys.ts — key generation + all 4 import methods
     4. src/crypto/encoding.ts — Base58Check, WIF, hex
     5. src/crypto/address.ts — address derivation for all 7 coins
     6. Unit tests for all crypto modules

     Phase 2: Account System

     7. src/crypto/aes.ts — AES-GCM-256
     8. src/account/account.ts — account ID derivation
     9. src/account/keystore.ts — encrypted JSON read/write
     10. src/account/key-manager.ts — key CRUD
     11. Unit tests

     Phase 3: UI Shell

     12. Navigation setup
     13. LoginScreen + CreateAccountScreen
     14. KeyListScreen + generate/import screens
     15. DashboardScreen (layout only)
     16. Zustand stores

     Phase 4: API Layer

     17. API interfaces + providers (Etherscan, Blockchair, FCH, custom)
     18. Wire to stores — Dashboard shows real balances

     Phase 5: UTXO Transactions

     19. BTC tx-builder
     20. BCH tx-builder (SIGHASH_FORKID)
     21. FCH tx-builder (extends BCH)
     22. DOGE tx-builder
     23. SendScreen + ReceiveScreen for UTXO coins

     Phase 6: ETH/ERC-20 Transactions

     24. ETH tx-builder
     25. ERC-20 tx-builder (USDT, USDC)
     26. SendScreen for ETH/ERC-20

     Phase 7: Polish

     27. TX history views
     28. Settings screen (API config)
     29. QR scanner
     30. Security hardening (memory wiping, screenshot prevention)

     Security Notes

     - Private keys never leave device — all signing is local
     - sha256(password) is weaker than PBKDF2/Argon2 for key derivation, but
     implementing per user spec
     - Random 12-byte IV per AES-GCM encryption (stored alongside ciphertext,
     not secret)
     - Clear decrypted keys from memory on app background
     - Validate imported keys are on secp256k1 curve
     - Validate addresses (checksums) before sending
     - Dust limits: BTC 546 sats, DOGE 1 DOGE — don't create sub-dust outputs

     Verification

     - Unit test all crypto functions with known test vectors (BTC/ETH address
     generation from known keys)
     - Test account creation/login cycle: create password → generate key → lock
     → re-enter password → verify decryption
     - Testnet end-to-end: generate key → fund from faucet → send TX → verify on
      explorer
     - Test each coin's address derivation against reference implementations
